# Discord-бот модерации клана

Бот на **Python (discord.py 2.x, слэш-команды)** с хранением данных в **SQLite**.

## Что делает бот

- `/проверка @юзер` — выдаёт роль "на проверке" на 7 дней. Если за это время не
  использовать `/проверен`, роль автоматически снимается и выдаётся роль
  "отклонён" ещё на 7 дней.
- `/проверен @юзер` — снимает роль "на проверке", выдаёт роль "проверен"
  (отменяет автоматическое отклонение).
- `/отклонен @юзер` — сразу выдаёт роль "отклонён" на 7 дней (можно использовать
  и без предварительной `/проверка`).
- `/бан @юзер длительность причина` — выдаёт роль бана на срок (7d, 5m, 10d, 1y и т.д.),
  автоматически снимается по истечении.
- `/мут @юзер длительность причина` — аналогично, роль мута.
- `/состав` — присылает embed со всем составом клана.
- `/добавить ник привилегия @юзер` — добавляет игрока в состав.
- `/удалить @юзер` — удаляет игрока из состава.

Все команды логируются embed-сообщением (ник, команда, время, дата) в лог-канал.
Раз в минуту фоновая задача проверяет, не истёк ли срок ролей, и снимает/выдаёт их.

## Важно: как я трактовал права доступа

В твоём описании после команд `/бан` и `/мут` шёл общий список из 6 ролей
("Прописывать эти команды могут роли с такими айди..."). Я применил его как
права для `/проверка`, `/проверен`, `/отклонен` (так как для них отдельного
списка не было указано), а для `/бан` и `/мут` оставил именно те списки ролей,
что были перечислены рядом с этими командами. Если это не так — роли легко
поменять в `config.py`, там всё вынесено в отдельные списки с комментариями.

## Установка

1. Убедитесь, что установлен Python 3.10+.
2. Установите зависимости:
   ```bash
   pip install -r requirements.txt
   ```
3. Скопируйте `.env.example` в `.env` и впишите токен бота:
   ```bash
   cp .env.example .env
   ```
4. В [Discord Developer Portal](https://discord.com/developers/applications) у вашего
   приложения включите **Server Members Intent** (Bot -> Privileged Gateway Intents).
5. Пригласите бота на сервер со следующими правами: `Manage Roles`, `Send Messages`,
   `Embed Links`, `View Channels`. Важно — **роль бота должна быть выше** всех ролей,
   которые он должен выдавать/снимать (проверка, отклонён, мут, бан, проверен).
6. Запустите бота:
   ```bash
   python main.py
   ```

## Структура проекта

```
moderation-bot/
├── main.py                 # точка входа, фоновая задача снятия ролей по таймеру
├── config.py                # все ID ролей/каналов и списки прав доступа
├── database.py               # работа с SQLite
├── requirements.txt
├── .env.example
├── cogs/
│   ├── verification.py       # /проверка /проверен /отклонен
│   ├── moderation.py          # /бан /мут
│   └── clan.py                 # /состав /добавить /удалить
└── utils/
    ├── duration.py             # парсер "7d 5m 10d 1y"
    ├── logger.py                # embed-логирование в канал
    └── checks.py                 # проверка прав по ролям
```

## Изменение ID ролей/каналов

Все ID вынесены в `config.py` — если что-то поменяется на сервере (новые роли,
другой лог-канал), достаточно поправить значения там, код трогать не нужно.

## База данных

При первом запуске автоматически создаётся файл `bot.db` (SQLite) с двумя таблицами:
- `temp_roles` — какие роли кому выданы и когда истекают (проверка/отклонён/мут/бан)
- `clan_members` — состав клана (discord_id, ник, привилегия)

## Ограничения / на что обратить внимание

- Роли "мут"/"бан" — это именно **роли** (как и указано в ТЗ), а не системный
  таймаут/бан Discord. Чтобы они реально ограничивали пользователя, на всех
  нужных каналах должны быть настроены **Permission Overwrites** для этих ролей
  (запрет отправки сообщений и т.д.) — это делается вручную в настройках канала.
- Если бот будет выключен дольше, чем осталось до истечения роли, снятие
  произойдёт сразу при следующем запуске (фоновая задача обрабатывает "просроченные"
  записи).
- `/добавить` использует `ON CONFLICT` — повторный вызов для того же Discord-пользователя
  обновит его ник/привилегию, а не создаст дубликат.
